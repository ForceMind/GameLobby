# Joyloop 静态原型评审与交付边界

## 评审输入

初版 `screens.zip` 与修订版 `joyloop.zip` 均为 HTML 参考文件，未附带其引用的完整 CSS、JS、SVG 与游戏封面资源。因此本仓库采用自包含 CSS、图标和代码原生插画重建，不能宣称逐像素复刻最终美术。

## v0.2.2 高保真原型更新

- 根路径 `index.html` 为给老板评审的原型基本说明首页，完整视口默认全屏，展示页面范围、主要交互、预设数据和评审用途，并保留模式选择和进入按钮；点击即可进入，主动选择半屏后进入 1:1 大厅，边长为 `min(viewportWidth, viewportHeight, 640px)`。大厅及其他业务入口不加全局同意门槛，默认全屏，仅由显式 `mode` 参数传递模式；旧 sessionStorage 布局缓存（包括 `accepted`）不读取。大厅不提供缩放按钮。
- half 是游戏优先精简模式：保留最近/热门/全部游戏与底部入口，隐藏排行榜、横幅、快捷大卡等次要内容；非游戏业务页以“前往 full”提示卡替代完整半屏内容。金币/宝石浮窗提供“获得”（活动页 full）与“充值”（商城 full），不加“+”号、不误回首页；half 货币栏从千位起使用 K/M，full 当前 52,860 保留完整，浮窗显示完整值并覆盖 9 位数。
- 可进入游戏先显示全屏加载；加载中左上角可用 `Lobby` 返回，进入游戏后只保留游戏右上角关闭按钮，关闭后恢复进入前模式。
- 金币、宝石与个人页资产卡原地打开余额和最近变动浮窗，不附加“+”或自动跳转；浮窗提供明确的“获得”（活动页 full）与“充值”（商城 full）入口。只有主导航、全部游戏和明确内容入口跳页，关闭浮窗不离开原页。个人页保留 ID 复制、等级、成就摘要和编辑资料，不提供独立退出登录。
- 商城统一美元口径：`1 USD = 10,000 金币`；礼包按固定金币数量与折扣价购买，不按折扣增加金币。
- 业务页面不放开发说明或旧货币文案；原型范围与预设数据说明保留在独立首页，技术接入细节保留在维护文档中。

## 当前交付与边界

项目提供七个独立 HTML 入口：原型说明首页、大厅、全部游戏、赛事、活动、商城、个人中心。筛选、导航、弹窗、表单、签到、转盘、任务、报名/候补、兑换码、商城确认和个人设置均有本地反馈。余额、订单、奖励记录、赛事结算和设置不是服务端持久化事实。

本地可交互游戏仅覆盖加载、进入、关闭以及少量局部操作（转轴或气泡）。它验证页面流程，不代表真实游戏引擎、实时对局、扣款或资产结算已经接入。

## 接入边界

`window.JoyloopHost` 可注入公共账号、钱包和请求方法。页面只发送版本化 `requestId/action/payload` 请求；宿主负责真实容器尺寸、App 账号、支付授权、服务端重价、到账确认与幂等处理。页面不会传递 token，也不会在桥接不可用时伪造成功。完整契约见 [HOST-INTEGRATION.md](../client/HOST-INTEGRATION.md)。

默认响应头为 `SAMEORIGIN`，顶层原生 WebView 和同源 iframe 可加载；跨源 iframe 需要另行确认允许域名、CSP 和宿主策略。
