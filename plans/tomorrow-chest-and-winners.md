# 明日宝箱与赢家动态：已确认实现契约

本文件覆盖 Lite v1 旧计划中「宝箱当月激活」「排除赢家榜与弹幕」的规定。当前范围：单个次日宝箱、今日赢家榜/最近中奖双标签、同源中奖弹幕。保留半屏底部 56% 布局、已隐藏的 Banner/成就/编辑资料/账号安全，不恢复赛事。

## 玩家流程与状态

1. 服务确认玩家在当前业务日完成至少一局有效游戏，解锁当日购买资格。进入页面或启动加载不算完成。
2. 支付报价的金币（首版预览 500）购买一个次日宝箱；每业务日限购一次，无自动续费、无月度激活。
3. 购买确认展示费用、开启时间、截止时间、奖励可能为零。预览默认 Asia/Shanghai 次日 00:00 开放，次日结束（再下一日 00:00，不含）截止。
4. 待开启状态展示明确时间与倒计时；服务器确认开奖和钱包入账后显示金额。开启与领取合并为一个原子动作，不增加一个看似扣款/到账的本地按钮。
5. 已开奖保存结果；重复点击、刷新和重试返回原记录，不重抽、不重复扣费/发奖。0 金币与过期是明确独立状态。
6. 昨日待开和今日可买独立展示，旧宝箱不阻止新的合法购买。已过期旧宝箱不能再开。

前台只描述「今天玩、今天买、明天开」及可能获得的金币。内部计算输入/公式、昨日损失和调整比例仅留在授权的服务端与后台审计；不得返回到玩家接口或展示在卡片、弹窗、规则、记录中。

## 数据源与接入边界

- 静态文案：`client/src/data/engagementMessages.json`，稳定 key 分 zh/en；新增领域不再用中文句子作 key。
- 默认 Pages 预览：`engagementPreview.json` + `createPreviewService`。浮动工具标明「预览数据」，所有账户与中奖事件是合成样例，不是真实账户、扣款或真实玩家战绩。
- 预览适配器按账号/场景独立保存到 localStorage；浏览器 Web Locks 可用时串行化跨页操作。存储不可用时显示错误，不伪装保存成功。
- `VITE_ENGAGEMENT_SOURCE=server` 或检测到原生宿主后启用服务器适配器。服务器请求失败不回退合成数据。身份由 HttpOnly 会话/宿主认证负责，不信任客户端传来的 playerId。
- 实际数据库、支付、签名游戏事件、概率/资格计算、分布式原子事务与生产权限**未接入**。预览状态机不能代替这些生产保证。

### API

| 接口 | 请求 | 响应/约束 |
|---|---|---|
| GET `/api/v1/chest/status` | 当前登录玩家 | `data: {serverTime,timeZone,eligible,offer:{version,day,priceCoins,maxRewardCoins,unlockAt,expiresAt},walletCoins,chests}` |
| POST `/api/v1/chest/purchases` | `day,offerVersion,idempotencyKey` | 同状态响应；服务端校验有效游戏、业务日、版本、余额及限购，锁定宝箱条款；客户端不决定金额 |
| POST `/api/v1/chest/open` | `chestId,idempotencyKey` | 同状态响应；验证归属、开放/过期、已有结果；开奖、钱包流水、状态变更原子提交 |
| GET `/api/v1/winners/today` | 当前登录玩家 | `data:{serverTime,timeZone,rankings,myRank,events}`；rankings 为前十；events 为当前最近中奖窗口（最多 50），使用唯一 ID、数值金币、毫秒时间戳、gameId |

`chests` 字段：`id,purchaseDay,unlockAt,expiresAt,status,rewardCoins,openedAt,offerVersion`。未开奖 `rewardCoins=null`，0 是合法开奖结果而不是缺失。业务日与时间均由服务器决定，显示倒计时以服务端时间加本地经过时间估算，不用于授权。

幂等键必须在服务端按认证玩家、操作和业务对象作用域隔离；数据库唯一约束 `(playerId,purchaseDay)`、`(playerId,chestId,reward)`。超时表示未知，不自动重试写入，提供状态查询；同一报价重试沿用业务键。409 表示资格/报价过期，用户刷新确认；缺失/畸形响应不作为成功。

## 赢家榜、列表与弹幕

### 幸运榜单与记录入口（最新修订）

- 宝箱卡片原底部「宝箱记录」位置为「幸运榜单」箭头折叠入口，默认收起；不再使用滑动开关。整行可点击，右箭头展开后转为向下；使用 `aria-expanded`，支持鼠标、Enter、Space。每次展开刷新今日前 5 名，数据仍与大厅游戏中奖榜分开。
- 同额时按开启时间较早优先，再按唯一事件 ID；只纳入当前业务日、已确认且正金币的开箱事件，去重并排除未来/其他日期记录。正式数据需先获得公开展示授权并脱敏。
- 原右上角「查看规则」改为「记录」按钮。打开「明日宝箱 · 记录与说明」浮窗，包含「记录 / 说明」两个标签，默认记录；方向键、Home/End 可切换，Escape 关闭后回到原按钮。
- 记录只显示当前玩家的宝箱、购买日期、可开启/截止时间、状态及获得金币；说明沿用已确认玩法。不再在主卡片底部展示或折叠个人记录。
- 排行读取独立 `GET /api/v1/chest/leaderboard`：`data:{serverTime,timeZone,entries:[{id,playerId,name,rewardCoins,openedAt,rank,isSelf}]}`，最多 5 条；支持加载、空数据、失败与重试。开箱成功后立即刷新排行，另每 30 秒刷新。
- 预览的开启事件位于 `engagementPreview.json` 的 `chestOpenings`，与游戏 `wins` 分开；自己的预览开箱结果参与当日排行。既有购买、次日开启、赢家榜和弹幕规则不变。

### 大厅赢家榜与中奖动态

- 同一组件两个键盘可操作的标签：今日赢家榜 / 最近中奖，保留我的排名。前者按当天累计中奖金币而非净收益排行；代表游戏取玩家最近一次事件。
- 最近记录按事件时间倒序；各标签每页 5 行，上一页/下一页。分页操作不改页面模式、不增加重新进入大厅的动作。
- 弹幕仅消费同一快照的事件 ID，按 ID 去重，不随机生成奖金/身份；轮询仅获取更新，不伪造新的事件。全屏最多四轨、半屏最多两轨。
- 每行/每条弹幕都有「我也要玩」，按 gameId 打开同一游戏说明浮窗；只有可用游戏可继续启动。
- 用户暂停、关闭接收、页面不可见、游戏运行/其他弹窗期间暂停弹幕；减少动态效果下不自动播放。仅按钮响应指针，不用透明大层阻挡页面。
- Banner 仍隐藏。半屏通过紧凑入口打开双标签浮窗，主体不超过底部约 56% 区域。

## 可重复的预览场景

普通链接默认新玩家：未完成游戏不可购买；完成页面内一局再回商城即可购买。该页面内游戏只是可交互流程，不作为生产有效事件。

仅预览适配器读取 `reviewScenario`；宿主/server 模式忽略该参数：

- `eligible`：可购买。
- `ready`：有一个次日待开启宝箱。
- `zero`：待开启且结果为 0。
- `expired`：过期宝箱。
- `low-balance`：余额不足（先完成一局解锁资格）。
- `empty`：没有赢家/中奖事件。

例如 `store.html?mode=half&lang=en&reviewScenario=ready`。每个场景的状态独立持久化；服务器端开奖结果不接受 URL 参数控制。
