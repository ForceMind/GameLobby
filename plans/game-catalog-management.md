# 游戏分类与游戏说明管理

## 已批准范围

用户确认补齐分类管理、游戏类型与展示分类解耦、按游戏维护多语言说明；保持既有游戏、门槛、运行状态和风格。不增加真实资金、权限或配置服务。当前分支与原 Pages 预览沿用同步授权，main 不变。

## 实现决定

- 分类使用共享种子和可审核目录，实际字段为 id / labels / enabled / sortWeight；all/popular 为系统筛选。已有游戏引用的分类不能停用或删除；校验覆盖两个环境的草稿与生效记录，并在审批/回滚时复查。
- gameType 独立于 tags，种子游戏显式迁移，决定是否展示 Slots 属性，不控制游戏引擎。
- 游戏说明按简介、玩法、规则管理，复用翻译目录与复核元数据；游戏编辑入口不要求操作员知道翻译键。简介中英文必填，玩法/规则可缺省但不能只填一种语言。
- 游戏说明和显示字段的已发布结果可保存至同浏览器预览；须显式 catalogPreview=1，真实宿主或 server 模式忽略。状态、门槛、地区、资产不由该展示预览覆盖。
- 目录发布不提供灰度/暂停假动作；较新草稿在回滚后保留，基线变化需重新提交。
- 分类页面明确展示草稿，玩家预览只消费生效数据。草稿和审核历史不持久化，不保证真实多人并发操作。

## 工作分界

- 主代理：数据契约、发布/引用保护、存储边界、后台集成、版本、测试与交付。
- Terra/high：CategoryManager 新组件；GameContentDialog 新组件；玩家目录/详情消费。各写入范围独立。
- 文档由说明编辑组件代理后续单独处理；分类组件代理只读复核主代理规则和存储边界。
- 独立审查发现的回滚覆盖新草稿和模拟灰度问题已修正，并增加定向回归；产品正文不包含派工或修订过程。

## 验证与交付

本地状态、行为和发布记录统一记入 client/QA.md。浏览器验证只修改本地会话与同源预览数据，测试分类/文案不进入静态种子或部署包。正式源码发布不包含原未跟踪交接文件或浏览器数据。
