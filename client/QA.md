# v0.2.5 静态资源、缓存与部署包验收

验收日期：2026-08-31。范围为本地生产构建、七个独立页面、简体中文与英文。

## v0.2.5 本轮功能验收

- PC 全屏大厅：热门游戏与今日赢家榜在同一行且顶部基线一致；DOM 实测两者 top 差值小于 2px。
- 全局获胜弹幕：屏幕内容层上方约 30% 区域最多同时展示四行“昵称、游戏、赢得金币”，按随机间隔投放，当前行未结束才占用下一行，满四行后排队；每条弹幕后有“我也要玩”入口并直接打开对应游戏；大厅、目录、赛事、活动、商城和个人页均渲染。
- 语言选择：原型入口与个人设置均使用自绘下拉菜单，页面不渲染原生 `<select>`。
- 商城活动卡：购买保障条目已移除，破产保险箱展示昨日净损、返还比例、每日刷新时间和 3 小时到账说明；刷新时间菜单可选择一次，选择后锁定至下月。
- 隐私设置：个人页设置包含接收他人获胜通知、允许发送我的获胜通知、向好友展示最近玩的游戏三个 switch；关闭接收后弹幕隐藏，关闭发送后不展示当前用户记录，关闭最近游戏展示后大厅标识变为“仅自己可见”。
- 响应式：移动端弹幕轨道高度 36px；半屏保持游戏优先布局。
- 当前为静态原型状态，隐私设置不持久化，获胜事件不连接推送服务。

## 当前交互契约

| 场景          | 行为                                                                           |
| ------------- | ------------------------------------------------------------------------------ |
| 原型说明首页  | 面向评审者解释页面范围、交互与预设数据；默认全屏，无勾选或确认，点击直接进入   |
| 半屏大厅/目录 | 游戏优先；保留最近、热门、全部游戏、筛选与底部入口，隐藏排行榜、横幅和大快捷卡 |
| 半屏个人页    | 显示资料、编辑入口、本周统计和资产卡；成就、战绩、安全设置等保留更多入口       |
| 半屏商城      | 显示四档真实礼包配置与购买确认；月卡、兑换码保留紧凑入口                       |
| 半屏活动      | 可领取今日签到和已完成任务、抽取转盘、查看奖励记录；展示任务简表               |
| 半屏赛事      | 显示三场赛事摘要、奖池、报名费和人数，可看规则、报名或加入候补                 |
| 更多内容      | 仅提示从全屏入口打开，不改变当前 URL 或布局，不用空提示页替代半屏内容          |
| 资产浮窗      | 显示完整余额与最近变动；获得进入当前布局的活动页，充值进入当前布局的商城       |
| 游戏          | 按既定流程临时全屏加载/运行，游戏右上关闭后恢复原页与原布局                    |

首页与业务页分开。页面内导航保持当前模式，不能把半屏直接改成全屏；只有从独立入口选择模式才能进入不同布局。业务页不读取旧布局缓存，不增加全局同意门槛。

## v0.2.4 本轮检查

- 已确认的用户报错：模块请求收到 `text/html`，不是已确认的 JavaScript API 兼容错误。线上当前脚本可正常返回，部分不存在的脚本路径却返回首页 200 HTML 并带长期缓存。尚未取得用户失败请求的准确 URL，不能把旧缓存认定为唯一原因。
- 修正：所有静态响应配置 `no-store`，JS/CSS 使用版本目录，提供全新说明入口，根级 404 禁止缺失资源回退首页。不修改产品页面设计、业务交互或强行改变响应 MIME。
- `check:dist` 检查所有七个页面引用的 JS/CSS 存在且位于当前版本目录，资产内容不是 HTML；新入口必须逐字等于 index；404 不依赖 JS；响应头不得保留一年 immutable 规则。
- 打包检查包含新入口与 404，逐文件比对解压后的 SHA-256，不允许遗留测试文件混入。
- `npm run verify` 通过：35 项测试、生产构建和增强后的资源检查。本地 MPA 预览的七个页面及新入口返回 200，新版 JS/CSS 返回正确类型，成功响应带 no-store，不存在的 JS 返回 404。Vite 预览不解释 Pages 的 `_headers`，其 404 不带预览自定义头；最终 Pages 响应头仍需部署后按指南检查。
- 浏览器实测新入口默认 full 可进入个人页；选择 half 后，金币浮窗充值进入半屏商城，四档礼包和返回入口保留。
- 尚未替用户上传本版或验证其手机；上线验收步骤见 [部署指南](DEPLOY-CF-PAGES.md)。

## 九位数显示规则

|        数值 | 半屏货币栏 | 全屏货币栏 | 浮窗与无障碍标签 |
| ----------: | ---------: | ---------: | ---------------: |
|       5,700 |       5.7K |      5,700 |            5,700 |
|      52,860 |      52.9K |     52,860 |           52,860 |
|   5,700,000 |       5.7M |       5.7M |        5,700,000 |
| 567,000,000 |       567M |       567M |      567,000,000 |
| 999,999,999 |         1B |         1B |      999,999,999 |

短格式最多一位小数，只改变展示，不改变钱包数值。半屏从千位、全屏从十万位开始缩写；个人页半屏资产卡同样用短格式，完整模式资产卡保留完整余额。

九位数已通过单元测试和公开宿主上下文的实际布局检查：320px 宽半屏中，567,000,000 与 999,999,999 在浮窗中完整显示，金额不溢出，获得/充值操作区可见。测试 HTML 不进入交付包。

## 保持不变的范围

- USD 礼包与折扣、昵称验证、游戏筛选、兑换码、转盘角度和宿主桥接测试继续通过。
- 大厅不添加缩放图标、货币加号或独立退出登录。
- 说明只放在独立原型首页；业务页展示实际内容，额外功能提示只在点击对应入口后出现。
- 游戏临时全屏是既有的游戏流程，不是半屏业务页面切换布局。
- 数据和结果仍供原型评审，不代表真实账户或服务端结算；宿主接口见 [HOST-INTEGRATION.md](HOST-INTEGRATION.md)。

## 发布复核

1. 执行 `npm run verify`，启动本项目的本地预览，确认地址实际显示 Joyloop。
2. 从首页进入 full/half，按上表检查内容与操作；半屏任何普通导航及获得/充值都应保留 half。
3. 在干净提交上运行 `npm run package:pages`。
4. 检查 ZIP 完整性、文件哈希与 manifest 的 `version/sourceCommit/dirty: false`。本轮未代为执行 Cloudflare 线上部署。
