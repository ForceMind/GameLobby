# v0.2.0 内嵌 H5 验收

验收日期：2026-08-28。范围为本地生产构建的六个页面、根入口别名、简体中文和英文。本文记录静态前端和桥接契约的验证，不代表真实 App、支付服务或游戏引擎已经联调上线。

## 验证结果

- `npm run verify`：ESLint、25 项自动测试、生产构建、七个 HTML 入口和相对资源路径检查通过。
- 七入口 × 两种语言 × 半屏/全屏 × 十组视口，共 280 组布局检查。主内容、页头和可操作内容没有非预期横向溢出；最近游戏列表的横向滚动是有意设计。
- 半屏宽高相等；全屏使用整个现有视口。英文默认页面正文及无障碍标签没有残留中文，语种选项自身的语言名称除外。
- 用户界面已清理开发说明、人民币和 CNY 定价。检查发现并修复了英文任务刷新说明、游戏维护状态重复以及“新上线/即将上线”的冲突标签。
- 对同意入口、半屏大厅、竖屏转轴游戏、横屏气泡游戏、购买确认和个人卡片做了截图检查。
- 修复半屏弹窗操作区被挤出可见区域的问题：标题和操作区保留，正文独立滚动。购买、宝石、资料、奖励记录和赛事弹窗均作了回归检查。

## 美元价格口径

基准为 `1 USD = 10,000 金币`。价格使用整数美分：`baseCents = coins / 100`，`priceCents = round(baseCents × (1 - discountPercent / 100))`。折扣不增加金币，宝石是独立赠礼。

| ---------- | ------: | ---: | ---: | -----: | -----: |
| `coin-6`   |   6,000 |    2 |   8% |  $0.60 |  $0.55 |
| `coin-30`  |  30,000 |   10 |  18% |  $3.00 |  $2.46 |
| `coin-68`  |  68,000 |   25 |  28% |  $6.80 |  $4.90 |

## 自动测试与失败处理

- 规则：Unicode 昵称长度、双标签/组合筛选、USD 折扣、兑换码分支、转盘目标角度。
- 入口：缺失或损坏会话不能跳过同意；合法会话和打开模式可恢复。
- 上下文：仅接受公共账号字段、1–999 的整数等级和非负安全整数余额，丢弃其他字段；部分更新保留有效旧值。
- 桥接：不支持的动作、错误币种、无宿主、异常、取消、超时和畸形响应不会成为购买成功；请求 ID 唯一，显式重试可沿用 ID。
- 窗口：同时只发一个显示请求，只保留最新排队请求；revision 单调递增；拒绝或同步异常后可继续；取消排队后可复用。
- 国际化：活动源码和数据词条有英文对应；动态占位符一致；语言内链保留筛选与锚点；活跃产品文案禁止开发说明和旧货币。

购买过程中所有礼包按钮锁定；12 秒未收到结果时保留锁并提示返回 App 查询，不自动重试。取消或明确失败可再次发起。只有宿主明确返回 `completed` 才显示购买记录，余额由宿主上下文更新，不能由前端加算到账。

窗口串行化不能取消已经发给原生的操作。宿主必须在真正写入尺寸前检查当前 WebView 文档与最新 revision，关闭/导航后丢弃旧请求；模式请求应快速完成。详见 [宿主接入契约](HOST-INTEGRATION.md)。

## 状态保留与限制

- 同意与打开模式保存于当前 WebView 的 `sessionStorage`。新会话再次询问；存储不可用时跨页再次询问。URL 的 `mode` 只选模式，不能代替同意。
- 语言由有效 `lang` 参数优先决定，其次读取可用的本地偏好，默认简体中文。入口和个人页均可切换。
- 奖励、转盘、报名、兑换、购买回执、昵称和设置为当前页面内存状态，刷新/换页会重置；不是持久账本。App 注入的账号和钱包是公共显示上下文，不是页面持有的登录凭据。
- 兑换测试夹具：空值、未知值、`USED-DEMO`、`OLD-DEMO` 为错误；`JOY-DEMO` 校验后需另点确认兑换，同页只可使用一次。测试代码不作为界面提示公开展示。
- 游戏画面是加载/进入/关闭流程及局部转轴或气泡交互；不连接真实游戏引擎、下注或结算。
- 原型包缺少被引用的样式与美术资源，当前为自包含重建，并非逐像素复刻证明。

## 尚未验证的外部条件

本轮未执行真实 iOS/Android WebView 联调、真实支付、服务端活动/赛事结算或 Cloudflare 线上部署。CSS 无法自行把小 WebView 扩大到设备全屏；App 必须实现容器切换。月卡定价、赛事计分/退款、奖励持久化等待确认事项见 [原型评审](../plans/joyloop_static_review.md)。

## 发布复核

1. 在 `client` 执行 `npm ci`、`npm run verify`。
2. 使用 `npm run preview`，按上表检查 `lang=zh/en` 与 `mode=half/full` 的组合。先通过说明入口再检查业务页面。
3. 在干净提交上运行 `npm run package:pages`。脚本会测试 ZIP 完整性、解压后逐文件 SHA-256 比对，并检查入口与资源。
4. 核对相邻 manifest 的 `version`、`sourceCommit` 与 `dirty: false`，按 [部署指南](DEPLOY-CF-PAGES.md) 上传对应包。不要使用旧 v0.1.0 的包替代本轮交付。
