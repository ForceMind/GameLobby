# v0.2.2 原型入口、半屏与资产回归验收

验收日期：2026-08-28。范围为本地生产构建、七个独立页面、简体中文与英文。

## 当前产品契约

| 场景               | 行为                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| `/` / `index.html` | 独立原型说明首页，向评审者解释页面范围、主要交互和预设数据；默认选全屏，无勾选、确认或禁用门槛，点击直接进入 |
| 完整大厅           | 保留最近游戏、目录、排行榜、活动推荐、快捷入口及各业务页                                                     |
| 1:1 半屏           | 游戏列表优先，保留最近/热门/全部游戏与底部入口；隐藏榜单、横幅、大快捷卡、卡片热度/分类/在线数等辅助信息     |
| 半屏其他功能       | 赛事、活动、商城、个人页保留入口，显示“全屏查看”提示；进入对应 full 页面，不返回原型首页                     |
| 金币/宝石          | 无加号，原地打开余额与最近变动浮窗；获得进入全屏活动页，充值进入全屏商城                                     |
| 游戏               | 加载时左上返回；进入后仅右上关闭；退出恢复原页和原大厅形态                                                   |

首页与大厅是不同页面。业务页不加全局同意状态，不读取旧布局缓存。`mode=half|full` 由进入按钮或明确链接传递，无参数的业务页默认 full；首页不继承旧 `mode=half` 链接的选择。

## 实测结果

- `npm run verify`：ESLint、29 项自动测试、生产构建、七个 HTML 入口和相对资源校验通过。
- 首页即使带旧 `mode=half` 参数，仍完整展示、默认 full。中英文均无 checkbox，进入按钮立即可用；默认点击进入 full 大厅。
- 主动选择 half 后进入 1:1 大厅。390×390 窗口首屏可完整看到四款热门游戏名称；封面、标题与不可用状态保留，辅助内容隐藏。
- 中英文半屏均隐藏赢家榜、活动横幅和快捷大卡；游戏目录在最近游戏之前。全部游戏的“全屏查看更多”进入 `games.html?mode=full`，不会误回大厅。
- 赛事、活动、商城、个人页 × 中英文，共 8 组半屏提示检查通过：不渲染完整业务大块，目标链接指向同一业务页的 full 模式。
- 资产浮窗的“获得”实点进入 full 活动页，“充值”实点进入 full 商城；关闭仍保留当前页面。两个动作位于可见的固定操作区。
- 半屏游戏进入后占满 390×844 视口，左上 Lobby 控件消失，右上关闭有效，返回仍是原 1:1 游戏列表。
- 浮窗 Tab/Shift+Tab 包含新获得/充值链接，能回绕至关闭按钮；未观察到浏览器控制台错误或警告。

## 九位数金额

|        数值 | 半屏货币栏 | 全屏货币栏 | 浮窗 / 无障碍标签 |
| ----------: | ---------: | ---------: | ----------------: |
|       5,700 |       5.7K |      5,700 |             5,700 |
|      52,860 |      52.9K |     52,860 |            52,860 |
|   5,700,000 |       5.7M |       5.7M |         5,700,000 |
| 567,000,000 |       567M |       567M |       567,000,000 |
| 999,999,999 |         1B |         1B |       999,999,999 |

短格式最多一位小数，允许四舍五入；它只影响货币栏展示，不改变钱包数值。半屏从千位、全屏从十万位开始缩写。

除单元测试外，通过公开宿主钱包上下文注入 `567000000` 与 `999999999` 做了实际布局测试：在 320px 宽、1:1 半屏下，货币栏为 `567M / 1B`；浮窗完整显示九位数，金额 `scrollWidth === clientWidth`，未溢出，获得/充值按钮可见。测试 HTML 只用于本地验证，后续构建清理，不进入交付 ZIP。

## 回归约束

- 说明页只在 `data-page="welcome"` 的 `index.html` 渲染，不拦截大厅或业务导航。
- 首页仅允许模式选择，不重新添加“已了解/同意”的勾选或确认状态。
- 大厅不重新增加缩放图标和货币加号；半屏的全屏入口是明确的内容导航。
- 业务页面不出现原型开发说明；评审用途说明仅在独立首页及文档中出现。
- 内链保持语言、筛选、锚点及明确模式；特殊目标 mode 优先于来源 mode。
- USD 礼包、昵称、筛选、兑换、转盘与宿主桥接的既有自动测试继续通过。

## 边界和复核

当前使用预设页面数据及本地游戏流程。真实支付、原生容器与服务端结算不属于本轮完成范围；接口契约见 [HOST-INTEGRATION.md](HOST-INTEGRATION.md)。本报告不是 Cloudflare 线上部署证明。

1. 执行 `npm run verify`，再运行 `npm run preview`。
2. 打开根路径：不选择任何额外选项即可进入 full；返回根路径主动选择 half，检查游戏优先布局。
3. 检查两种资产浮窗的完整值和获得/充值目标、半屏业务入口及游戏关闭。
4. 在干净提交上运行 `npm run package:pages`，核对 ZIP、SHA-256 和 manifest 的 `version/sourceCommit/dirty: false`。
