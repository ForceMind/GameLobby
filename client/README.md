# Joyloop 内嵌 H5 Lite v1

顶部 Joyloop 品牌下方显示当前构建版本号 `v0.3.4`，入口页、业务页、文档和后台保持一致。

2026-09-09 的 v0.3.4 已部署至 [Pages 分支预览](https://lobby-admin-lite-v1.joyloop.pages.dev)，部署源码为 `9d46fa7`；本次唯一地址、校验包与线上验证见 [部署记录](DEPLOY-CF-PAGES.md)。

这是 Joyloop 游戏大厅的 React + Vite 静态前端，面向内置在 App 中的 H5，也可独立作为 Cloudflare Pages 静态站点预览。当前代码不连接真实数据库、鉴权、游戏引擎或支付服务；宿主接入方式见 [HOST-INTEGRATION.md](HOST-INTEGRATION.md)。

## Lite v1 范围

- 前台只保留大厅、游戏、活动、商城、我的五个入口。
- 活动页只包含七日签到、幸运转盘、每日任务和奖励记录。
- 商城包含基础金币礼包、月度特权卡和明日宝箱；不保留兑换码、复杂促销或排行榜。
- 赛事、直播、家族/派对、声音/震动设置不属于本版本；今日赢家榜、最近中奖双标签和弹幕已恢复；语言切换仅在原型浮窗提供。
- 基础展示内容由 `src/data/` 下的 JSON 导入；余额、活动进度、订单、奖励和游戏实时状态预留服务端 API。
- 当前仓库为静态前端与后台原型；没有宿主或服务端时，不显示伪造的支付成功、开奖、结算或到账。

## 页面入口

面向 UI 的游戏大厅规范见 [玩家侧规范目录](../docs/ui/README.md)，按大厅、游戏、活动、商城、个人中心分模块；`docs.html` 的“游戏大厅 UI规范”区可下载。

Vite 会生成八个入口：`index.html`（独立原型说明首页）、`docs.html`（产品与运营文档）、`lobby.html`、`games.html`、`events.html`、`store.html`、`profile.html` 和 `admin.html`（运营后台原型）。生产输出位于 `dist/`。

## 运营后台原型

v0.3.4 将配置页面统一为只读预览：明确的编辑按钮打开分组标签弹窗，切标签保留临时修改，取消不写共享草稿。游戏排序/推荐单独编辑，运行状态单独立即生效；签到、转盘、任务不再在页面直接编辑。保存、审核、生效和操作失败分别反馈，详见 [验收记录](QA.md)。

`admin.html` 是从首页进入的桌面端运营后台原型，采用浅色企业后台布局，覆盖运营概览、待办与发布审核、游戏管理、签到/转盘/任务、商品与权益、订单、钱包流水和玩家管理。各模块使用与前台能力对应的 Mock 数据，支持上下文主操作、搜索、状态筛选、详情抽屉、新建配置草稿、游戏表格/卡片视图、拖拽排序、版本检查、环境切换、提交审核和状态流转展示。

后台原型不连接真实鉴权、数据库、钱包、支付或结算服务；正式接入时应按产品与运营文档中的状态、权限、审批、幂等和审计契约替换 Mock 数据。

游戏进入门槛第一期已接入：财富、魅力、金币余额、账号等级、性别及家族归属共同决定能否启动，运营标签只影响展示。Golden Pharaoh 财富门槛为 5，演示账号财富为 3，卡片保留并锁定；Fish Hunter 为家族专属，演示账号有家族可进入。地区白名单继续控制目录可见性。门槛改动经过草稿、逐字段审核和回滚；仅运行状态、维护公告保持紧急生效。

后台草稿和生效版本仍保存在当前后台页面内存，刷新会重置；玩家页使用与后台种子同源的静态游戏配置。后台点击发布不会跨页面持久同步玩家目录。开发验收入口 `/qa/game-gates.html` 可输入宿主事件、绕过卡片直接调用公开 `openGame` 并查看拒绝结果；加 `?host=missing` 验证真实宿主缺字段。该入口不属于生产构建输入。

v0.3.0 另生成带随机后缀的 `start-v0.3.0-<token>.html`（与说明首页完全一致的新 URL），用于部署后避开旧入口缓存；JS/CSS 放在 `assets/release-0.3.0-<token>/`，同一包内所有 HTML 共用这一批版本化资源。每次生产构建都会重新生成 16 位随机十六进制 token。所有响应配置 `Cache-Control: no-store`，移除原来覆盖 `/assets/*` 的一年 immutable 缓存。根目录 `404.html` 让 Pages 对不存在的路径返回 404，不再将缺失脚本替换成首页的 200 HTML。不能通过更改 HTML 的 MIME 类型伪装修复脚本缺失。

此策略优先保证频繁更新的原型一致性，会增加重新打开页面时的资源下载。旧浏览器或 CDN 已存储的响应不能由新包追溯删除，因此发布后请先用新入口验证；若自定义域名有强制缓存或重写规则，需另行在 Cloudflare 控制台调整，不能靠 ZIP 覆盖这些规则。

五个业务页之间使用 History API 切换内容，保留 H5 外框、顶部资产栏、底部导航和宿主上下文，不再逐次重载 HTML。页面标题、导航选中项随路由更新；新导航从内容顶部开始，历史导航恢复已记录的滚动位置，筛选和锚点保留。直接打开、刷新与新窗口仍使用对应 HTML 入口，说明首页保持独立。

左上角始终有返回入口：游戏、活动、商城、个人页返回当前布局的大厅；真正退出大厅时先显示旧版复用的二次确认，确认后才请求宿主关闭 H5 或返回原型说明首页。这不是退出登录，也不会把半屏业务页直接变成全屏。半屏个人页保留资产总览、最近流水与设置入口；流水详情可按币种和收支筛选。

## 进入与游戏流程

首页 `index.html` 是给老板评审的原型基本说明页，完整视口默认选择全屏；展示页面范围、主要交互、预设数据和评审用途，并保留模式选择和进入按钮。点击即可进入，用户主动选择半屏后进入屏幕下方约 50–60% 高度的大厅，不再要求 1:1 比例。大厅及其他业务入口不加全局同意门槛，直接打开时默认全屏；只有显式 `mode=half|full` 才传递指定模式。旧版本 sessionStorage 布局缓存（包括 `accepted`）不读取。大厅内不提供半屏/全屏缩放按钮。half 为游戏优先精简模式，仅保留最近/热门/全部游戏与底部入口；排行榜、横幅、快捷大卡等次要内容隐藏，个人、商城、活动仍展示各自的实际精简内容，更多功能只提示从独立首页选择 full，不导航或改 mode。half 内所有业务导航、获得和充值均保持 half。CSS 只能使用宿主分配的视口；真实容器扩展由原生 App 配合。

说明首页和每次构建的新入口默认简体中文，不继承浏览器、宿主或先前玩家页的英文选择；只有明确的 `lang` 参数可覆盖。玩家页面继续沿用原有语言优先级。

桌面模拟手机的固定比例共用高度 `min(860px, 视口高度−64px)`，18:9 宽度为高度的 1/2，21:9 为3/7，切换时真正改变宽度；自动档保留内容适配。16px 圆角是通用示意，不是某款手机的硬件复刻。桌面预览安全区上下至少12px、左右至少8px，并与真实设备的 `env(safe-area-inset-*)` 取较大值。真实手机不添加模拟边框或人为安全区。

点击可进入游戏后，加载和游玩始终在同一设备框内部展示。加载中左上角显示本地化的返回按钮，游玩时右上角显示关闭按钮；内容可在短窗口内滚动，按钮不随内容卷走。半屏入口进入游戏时视觉容器变为全屏，关闭后恢复原半屏；原生宿主的展示模式请求保持不变。仓库内游戏画面是本地交互流程，不是实际游戏引擎或实时对局。

页面使用当前 App 账号，不提供独立登录或退出登录；账号身份和注销由 App 管理。宿主可注入公共 `account` 与 `wallet`，或通过 `joyloop:context` 事件更新。

个人页不展示账号安全、异常登录检测、编辑资料、成就或本周概览。「设置」提供中奖弹幕总开关及原有中奖分享/最近游戏隐私项，按账号保存；没有声音、震动设置。中英文切换仅供原型浮窗查看使用。

## 语言与资产

货币栏短格式规则：半屏从 `1,000` 起、全屏从 `100,000` 起使用 K/M/B，最多一位小数；较小金额使用完整千分位。浮窗及无障碍标签始终使用完整值。例如半屏 `5,700 → 5.7K`、`52,860 → 52.9K`，九位金额 `567,000,000 → 567M`，浮窗仍显示 `567,000,000`。

金币、宝石及个人页资产卡均原地打开余额与最近变动浮窗，关闭不改变页面或滚动位置，不附加“+”按钮；浮窗提供“获得”（当前布局的活动页）与“充值”（当前布局的商城页），不会切换 full。half 货币栏从千位起使用 K/M 缩写，full 的当前 52,860 保留完整；更大的数值仍使用短格式，浮窗显示完整值并覆盖 9 位数。主导航和明确的内容入口才进行页面跳转，且在 half 内保持 half；详情、规则、表单和游戏操作不转回首页。

正式支持 `zh`（简体中文）和 `en`（英文）。商城统一使用美元：`1 USD = 10,000 金币`。当前静态礼包配置如下：

|    金币 | 折扣 |   原价 | 折后价 |
| ------: | ---: | -----: | -----: |
|   6,000 |   8% |  $0.60 |  $0.55 |
|  30,000 |  18% |  $3.00 |  $2.46 |
|  68,000 |  28% |  $6.80 |  $4.90 |
| 128,000 |  40% | $12.80 |  $7.68 |

折扣档位属于业务最终确认前的静态配置；折扣不增加金币数量，宝石赠礼是独立字段。购买按钮进入确认页，再通过宿主 `purchase` 请求处理；宿主未接入时不会显示购买成功。

## 本地运行、验证与打包

使用 Node.js 22.12 或更新版本（`.nvmrc` 选择 Node 22）：

```bash
npm ci
npm run dev
npm run build
npm run preview
npm run verify
npm run package:pages
```

打包脚本在仓库根目录 `artifacts/` 生成 ZIP、`.sha256` 和 manifest；正式包应来自干净提交，manifest 的 `dirty` 应为 `false`。不要直接双击 HTML，请通过本地 HTTP 预览。

## Cloudflare Pages

Git 集成设置：Root directory=`client`，Build command=`npm run build`，Build output directory=`dist`。直接上传见 [DEPLOY-CF-PAGES.md](DEPLOY-CF-PAGES.md)。`public/_headers` 会随构建复制到 `dist/_headers`。

当前 `_headers` 使用 `SAMEORIGIN`，允许顶层原生 WebView 和同源 iframe；跨源 iframe 需另行明确允许域名、CSP 与宿主策略。

进入后台「多语言内容」，选择语言与范围后导出 CSV；译者只改「操作」与「译文」，回传后逐条预览并确认写入会话草稿。原文变化会触发待复核。完整步骤、文件字段及冲突处理见 [翻译工作流程](../docs/translation-workflow.md)。当前保存和模拟审核均只在后台会话内有效，刷新重置，不会更新玩家端。
