# 明日宝箱

**产品功能需求说明书 · Tomorrow Chest**

**适用团队：**产品、运营、设计、前端、后端、测试  
**文档日期：**2026 年 10 月 16 日

本文用于定义明日宝箱的功能目标、参与规则、奖励计算、领取与退款条件、界面状态及验收口径，供相关团队开展产品设计和开发测试。

## 核心业务机制

| 业务环节 | 产品规则                                                             |
|--------------|--------------------------------------------------------------------------|
| 获得资格     | 完成一局指定的有效游戏，获得一次宝箱购买资格。                           |
| 购买宝箱     | 使用金币购买，示例价格为 500 金币；每次只可持有一只未处理宝箱。          |
| 次日开启     | 购买后在次日 00:00 解锁，在规定时限内由用户主动开启并领取奖励。          |
| 奖励计算     | 依据统计期内的净亏损（游戏投入 − 游戏派奖 − 已领取宝箱奖励），确定随机上限及折算比例。 |
| 奖励抵扣     | 宝箱奖励成功到账后，按实际到账的全部金币金额抵减之后开奖所使用的净亏损。 |
| 过期处理     | 到期时固定计算“本可领取奖励”；用户返回活动页后，可主动申请退回购箱本金。 |

> **活动参数**  
> 示例配置：购买价 500 金币；基础随机范围 10～10,000；次日 00:00 可开启；开放后的下一个 00:00 到期。实际活动使用已配置的价格、时间和奖励参数。

## 完整活动流程

参与一局有效游戏 → 获得购买资格 → 支付金币购买宝箱 → 等待次日开启 → 领取奖励（到账金额计入后续净亏损抵扣）→ 再次参加游戏。若逾期未开启：到期计算并保存未领取金额（不计入亏损抵扣）→ 用户查看过期结果 → 主动申请退回购买本金 → 再次参加游戏。

## 01 产品目标与玩法结构

“明日宝箱”是一项通过“今日参与—今日购买—明日回访—领取结果”的循环来促进用户有效游戏参与及次日回访的活动。活动的中心是宝箱卡片；用户无需离开活动页即可了解条件、价格、状态与下一步行动。

### 1.1 用户完整旅程

完成一局有效游戏 → 获得购买资格 → 支付 500 金币 → 等待次日 00:00 → 在可领取时段内开启并得奖 → 再次参加游戏获取下一轮资格。

若未按时开启：到期自动记录“原本可获奖励” → 用户回访并查看未领取提示 → 主动申请返还购买成本 → 再次参加游戏获取下一轮资格。未实际到账的奖励不影响净亏损。

### 1.2 活动规则与参数

| 产品项目 | 产品规则 / 参考配置                                        |
|--------------|----------------------------------------------------------------|
| 活动门槛     | 完成一局指定的有效游戏；有效结果以该局正常结算为准。           |
| 资格使用     | 一次资格只可购买一只宝箱；当日有效，购买后即消耗。             |
| 购买价格     | 500 金币，购买时直接扣除。                                     |
| 购买数量     | 同一用户同一时间最多 1 只待处理宝箱；每日最多购买 1 只。       |
| 开启时间     | 购买后的下一个活动自然日 00:00:00。                            |
| 领取有效期   | 从开放时刻起至再下一个活动自然日 00:00:00 之前，共一个自然日。 |
| 活动时间口径 | Asia/Shanghai（北京时间，UTC+8）；不随设备所在地改变。         |
| 统计亏损周期 | 以奖励计算时刻向前回溯 7 × 24 小时；运营可配置。               |
| 净亏损抵扣     | 统计期内实际领取的明日宝箱金币奖励，视作游戏收益，抵扣用户净亏损。 |
| 随机数范围   | 原始下限 10、原始上限 10,000；实际范围随亏损变化。             |
| 返还规则     | 仅宝箱过期且未领取时可主动申请，退回实际购买成本。             |

> **运营配置规则**  
> 活动价格、时间、参与资格、奖励数值均以活动配置为准。用户购买宝箱时确定的规则及购买成本不因后续运营配置变化而改变。

## 02 状态与生命周期

页面只展示用户当前最重要的一步；“已开启”“已退款”应作为历史结果保留，并不阻止用户完成新一轮游戏。

| 用户可见状态 | 触发条件                         | 主操作与结果                           |
|------------------|--------------------------------------|--------------------------------------------|
| 待参与游戏       | 当前无待处理宝箱，也没有可用购买资格 | 去玩游戏；完成后变为可购买。               |
| 可购买           | 已完成当日有效游戏，且符合限购条件   | 购买宝箱，消耗资格并扣金币。               |
| 等待开启         | 购买成功，尚未到次日 00:00           | 展示开启倒计时；不可提前打开。             |
| 可以开启         | 已经到开启时间，仍未超过领取期限     | 点击开启，计算并实际发放金币奖励。         |
| 过期可退款       | 超过截止时间仍未开启                 | 展示已计算的“未领取奖励”及申请退款按钮。   |
| 已开启           | 用户已开奖并领取成功                 | 展示奖励结果；关闭后回到新一轮待参与状态。 |
| 已退款           | 用户主动申请退款成功                 | 展示退回金额；关闭后回到新一轮待参与状态。 |

### 2.1 关键状态优先级

- 优先展示仍待处理的旧宝箱：先判断是否已过期，其次是否可开启，再次是否仍在等待。
- 没有待处理宝箱时，才判断今日是否达到限购、是否有购买资格、是否需要先玩游戏。
- 领取成功或退款成功后，历史记录照常保存；新的一只宝箱需要新的有效游戏记录。
- 同一只宝箱的最终结果只能是“已领取奖励”或“已退款”，两种结果互斥。

## 03 参与资格与购买规则

### 3.1 有效游戏与资格

- 用户从活动页点击“去玩游戏”，进入指定游戏或游戏列表；只有完成一局并正常产生结算结果才获得资格。单纯点击跳转、进入房间或中途退出不计入。
- 默认有效资格属于游戏结算发生的活动自然日，至当日结束前有效；跨午夜完成的游戏按结算时刻所属自然日计算。
- 资格只能用于购买一次；即使当日完成多局游戏，也不会因此突破每日购买次数上限。
- 若宝箱正在等待开启、可开启或过期待退款，期间完成的其他游戏不预存为下一轮资格；只有处理上一只宝箱之后的新游戏才算下一轮参与。

### 3.2 购买宝箱

- 满足购买资格、当天购买次数未达上限、无未处理宝箱且金币足够时，才显示有效的“购买宝箱”操作。
- 购买界面明确展示价格 500 金币，并在确认后扣除；取消购买不消耗资格或金币。
- 余额不足时提示“金币不足”；购买失败时不得视为完成购买，不得进入等待状态。
- 同一次用户操作即使误触多次，也只能生成一只宝箱、扣款一次。
- 购买完成立即展示“明日 00:00 开启”及剩余等待时间。

## 04 开启、发奖、过期与退款

### 4.1 等待阶段

宝箱在可开启前显示倒计时，文案示例：“明日 00:00 可开启”。页面持续打开时可实时更新展示；状态以活动统一时间为准，而非用户设备显示的时间。

### 4.2 领取奖励

- 到达开放时刻，按钮从“等待开启”变为“开启宝箱”。
- 用户点击后，按第 5 章的奖励规则使用开启当时的最近亏损计算一次奖励。
- 开启成功后，金币奖励实际到账，播放宝箱动画并展示奖励弹窗、奖励金额和“继续玩游戏”。本次实际到账的全部金币奖励（包括公式中的购买价格返还部分）视同游戏收益，参与之后宝箱开奖的净亏损计算；本次开奖自身使用的是发奖前的净亏损，避免循环计算。
- 用户关闭获奖弹窗或离开页面，不影响已完成的领奖；再次进入时不重复发奖。

### 4.3 到期自动计算“未领取奖励”

- 到达过期时刻且宝箱尚未开启时，系统自动为这一只宝箱按相同算法计算一次真实的“原本可获奖励”，保存结果供以后查询。
- 此处的奖励仅是未领取的历史结果，不进入用户金币余额，不抵扣净亏损，也不能在过期后补领。
- 计算时使用“过期时刻之前的统计周期亏损”，不是用户下次登录时的亏损；开奖结果冻结不再改变。
- 用户之后打开活动页时，可查看“上一只宝箱已过期，本可获得 6,000 金币”等真实提示。

### 4.4 用户主动退款

- 过期后展示“申请退回 500 金币”；即使用户长时间未登录，也不会因为超时而自动退还购买款。
- 只有用户点击申请并成功处理，500 金币才实际退回余额，页面才显示“已退回 500 金币”。
- 退款金额按这只宝箱购买时实际支付的金币计算，不按当前新价格，也不按预计算的奖励金额。购箱成本本身不计入游戏投入，因此退回购箱成本也不作为游戏收益或宝箱奖励抵扣净亏损。
- 退款前无法购买下一只宝箱；退款成功后须重新完成一局有效游戏，才有下一轮购买资格。
- 同一只宝箱只可退款一次；已领奖宝箱不可退款，已退款宝箱不可补开奖。

### 4.5 时间示例

| 时间（北京时间）   | 宝箱展示                                | 允许的用户操作                 |
|------------------------|---------------------------------------------|------------------------------------|
| 10 月 15 日 20:30 购买 | 等待开启；显示到 10 月 16 日 00:00 的倒计时 | 查看规则与记录。                   |
| 10 月 16 日 00:00:00   | 立即切换为“可以开启”                        | 可以开启并领取真实奖励。           |
| 10 月 16 日 23:59:59   | 仍在领取期限内                              | 可以开启并领取真实奖励。           |
| 10 月 17 日 00:00:00   | 立即变为过期待退款，同时固定“原本可获奖励”  | 不能再领奖；可主动申请退款。       |
| 10 月 20 日再次访问    | 仍显示未领取结果和待退款金额                | 点击申请退款；成功后退回购买成本。 |

> **领取与过期的区别**  
> 领取区间为“开启时刻（含）至过期时刻（不含）”。过期后可以继续展示真实未领取奖励，但不能将其作为已发放金额加入钱包、榜单或实际发奖记录。

## 05 奖励计算规则

### 5.1 计算口径与变量

| 符号 / 概念     | 定义与产品口径                                                          |
|---------------------|-----------------------------------------------------------------------------|
| P：购买价格         | 这只宝箱购买时实付金币，示例为 500。                                        |
| M：随机原始上限     | 活动配置的最大随机值，示例为 10,000。                                       |
| m：随机原始下限     | 活动配置的最小随机值，示例为 10。                                           |
| L：用户统计期净亏损 | 统计期内“符合条件游戏的投入 − 游戏派奖 − 已实际领取的本活动宝箱奖励”的非负余额，最低为 0。 |
| T：统计结束时刻     | 正常开启时为实际开启时刻；过期未开时为该宝箱的过期时刻。                    |
| C：已领取宝箱奖励合计 | 统计期内在 T 之前实际到账的本活动宝箱奖励总额，每笔成功领取记录只计一次。 |
| U：实际随机上限     | U = min(M, L)，即不超过原始随机上限，也不超过用户净亏损。                   |
| k：奖励折算比例     | 根据 L 与 M 的倍数采用 50% / 60% / 100% 三档。                              |

净亏损的统一计算公式为：

```text
G = 统计期内符合条件游戏的投入金币合计
W = 统计期内符合条件游戏的结算派奖金币合计
C = 统计期内已经实际到账的明日宝箱奖励金币合计
L = max(0, G - W - C)
```

- **宝箱奖励视同游戏收益：**以用户实际领取、实际到账的奖励金额计入 C，包含奖励公式中的购箱价格 P 部分及额外随机奖励部分；它会减少后续宝箱计算使用的 L，也可能使比例从 100% 降至 60% 或 50%，或者缩小实际随机上限。
- **到账才计入：**只有在统计期内成功领取并入账的宝箱奖励才能计入 C；购买成功但尚未开启、已到期但未领取、系统仅预先计算的“本可获得奖励”均不计入。
- **避免循环计算：**当前宝箱在计算奖励时，仅统计 T 之前已到账的历史宝箱奖励；当前这只宝箱即将发放的奖励不先扣减自己的 L，发放成功后才影响下一只宝箱。
- **购买与退款不参与：**购买宝箱扣除的金币不作为游戏投入；过期退回的购箱成本也不视为游戏派奖或宝箱奖励。统计期内如发生上述交易，均不改变 G、W、C。
- **统计区间与去重：**默认回溯 T 之前最近 7 × 24 小时，运营可配置。以各笔游戏结算、宝箱奖励实际到账的时间归入对应统计期；同一笔奖励只抵扣一次。统计期净额为负时按 L = 0 处理，不产生负的随机上限。


### 5.2 亏损对应的三档折算比例

| 用户净亏损 L    | 本次折算比例 k | 以 M = 10,000 举例     |
|---------------------|--------------------|----------------------------|
| `L < 5 × M`          | 50%                | L 小于 50,000 金币。       |
| `5 × M ≤ L < 10 × M` | 60%                | L 为 50,000～99,999 金币。 |
| L ≥ 10 × M          | 100%               | L 从 100,000 金币开始。    |

三档采用阶梯规则，不在 50%～60%～100% 之间平滑插值；达到门槛的瞬间即切换新比例。门槛比较使用**抵扣已到账宝箱奖励后的 L**，始终以原始随机上限 M 为基准，而不是调整后的 U。

### 5.3 随机抽取与最终奖励

1. 先计算实际随机上限：U = min(M, L)。
2. 若 U ≥ m，则从包含两端的整数区间 [m, U] 中等概率抽取随机值 X。
3. 若 `0 < U < m`，则 X 固定为 U；若 U = 0，则 X = 0。这样在亏损很少时仍能得到确定、可计算的结果。
4. 最终奖励 = P + 向下取整（X × k），金币按整数发放。

### 5.4 数值示例（P = 500，m = 10，M = 10,000）

| 净亏损 L | 比例 k | 实际 X 范围 | 最终奖励范围（金币） |
|--------------|------------|-----------------|--------------------------|
| 0            | 50%        | 固定 0          | 500（无额外奖励）        |
| 6            | 50%        | 固定 6          | 503                      |
| 2,000        | 50%        | 10～2,000       | 505～1,500               |
| 20,000       | 50%        | 10～10,000      | 505～5,500               |
| 50,000       | 60%        | 10～10,000      | 506～6,500               |
| 100,000      | 100%       | 10～10,000      | 510～10,500              |

> **宣传展示与奖励结算**  
> 活动宣传文案（如“最高有机会获得 10,000 金币”）可单独配置，仅用于界面展示。实际奖励由上述公式决定，不以宣传数值作为计算上限。示例参数下，净亏损达到 100,000 金币时，理论最高奖励为 10,500 金币。

### 5.5 已领取宝箱奖励抵扣示例（M = 10,000）

**示例 A：领取后从 60% 档降为 50% 档**

```text
统计期内有效游戏投入 G           = 80,000 金币
统计期内游戏派奖 W             = 28,000 金币
未扣除宝箱奖励时的净游戏亏损     = 52,000 金币
统计期内此前已领取宝箱奖励 C    =  6,000 金币
本次使用的净亏损 L = 80,000 - 28,000 - 6,000 = 46,000 金币
```

如果不考虑已领取宝箱奖励，52,000 金币达到原始随机上限的 5 倍，比例为 60%；实际扣除 6,000 金币已领取奖励后，L 为 46,000 金币，不再达到 5 倍门槛，本次比例为 **50%**。

**示例 B：宝箱奖励超过游戏净亏损**

```text
游戏投入 G = 20,000；游戏派奖 W = 16,000
此前已领取宝箱奖励 C = 6,000
L = max(0, 20,000 - 16,000 - 6,000) = 0
实际随机值 X = 0，本次奖励 = 购买价格 P
```

这只是单次奖励计算时的净亏损下限处理，并不追溯改变已到账的宝箱奖励。

**示例 C：过期但未领取**

某宝箱过期时计算出“本可获得 6,000 金币”，但用户没有实际开启和领取。这 6,000 金币仅用于过期提示与历史记录，**C 不增加，L 不因此减少**。之后申请退回的 500 金币购箱成本同样不计入 C。

### 5.6 计算时机与开奖结果归属

- 正常领奖：仅在用户有效点击开启时计算一次 X 和最终奖励，并发放该金额。**实际发放成功后**，本次全额奖金在其到账时间起参与未来统计期的 C，降低后续宝箱的 L。
- 过期未领：仅在到期时计算一次 X 和最终奖励，保存为“本可获得奖励”，不发放、不计入 C；计算该过期宝箱时，仍需扣减到期前统计期内其他已到账宝箱奖励。
- 同一只宝箱不会同时出现实际领奖结果与“本可获得”结果；任何情况下均不得重新随机。
- 购买时的价格、随机上下限、比例阶梯、统计周期等规则为该宝箱的历史规则依据；统计亏损 L 则按规定的开奖 / 到期时刻计算。

## 06 页面功能与交互

### 6.1 活动主卡片

主活动功能区建议接近 1:1 卡片比例，移动端优先。卡片包含“明日宝箱 / Tomorrow Chest”标题、说明入口、宝箱插画、宣传利益点、参与步骤、当前状态与唯一主操作；页面可展示用户当前金币余额。

| 状态        | 主按钮          | 辅助说明 / 反馈                      |
|-----------------|---------------------|------------------------------------------|
| 待参与游戏      | 去玩游戏            | 今天完成一局有效游戏，即可解锁购买资格。 |
| 可购买          | 购买宝箱 · 500 金币 | 购买后明日 00:00 可开启。                |
| 等待开启        | 等待开启（不可点）  | 显示小时、分钟、秒倒计时。               |
| 可以开启        | 开启宝箱            | 开启动画与金币到账弹窗。                 |
| 过期待退款      | 申请退款 · 500 金币 | 提示“原本可获得 N 金币”，但未到账。      |
| 已领取 / 已退款 | 继续玩游戏          | 结果弹窗关闭后回到新的参与循环。         |

### 6.2 页面弹窗

- 活动说明：游戏资格、购买价格、次日可开、过期处理、奖励介绍及玩法规则。
- 开启记录：历史宝箱的购买时间、开启或过期时间、实际领取金币／未领取金额、退款金额及状态。
- 购买确认：明确购买价格、扣款行为、开启日期和领取期限。
- 开奖成功：展示实际获得金币及“继续玩游戏”入口。
- 过期提示：展示固定的“本可获得奖励”，说明已错过领取，并提供退款操作。
- 退款成功：明确“已退回 500 金币”，提示需再玩一局才能重新购买。

### 6.3 幸运榜单

- 活动主卡片下方提供“今日幸运榜”，默认收起，点击后展开 5 位当日实际领取较高奖励的用户。
- 每一项展示头像、昵称、实际到账金币数；排行榜按本活动统一时区的当天自然日统计。
- 过期后仅记录“本可获得”的奖金不得计入幸运榜；无数据时显示温和的空状态。

### 6.4 多语言

默认界面语言为英文（English）。语言选择包含 English、简体中文、繁體中文、हिन्दी、Bahasa Indonesia、ไทย、Tiếng Việt、Español、Português (Brasil)、العربية，共 10 种。

活动名称、规则、时间提示、余额、按钮、排行榜、历史记录、错误提示与所有弹窗保持同语言；语言切换不改变真实业务状态、币值或时间；阿拉伯语使用从右向左的布局。

## 07 补充业务边界与异常提示

| 场景                   | 产品必须表现的结果                                     |
|----------------------------|------------------------------------------------------------|
| 只进入游戏，未完成有效对局 | 不授予购买资格；提示完成一局。                             |
| 金币不足 / 用户取消购买    | 保持资格和原余额；宝箱不进入等待状态。                     |
| 宝箱已有待处理状态         | 不得再购买第二只；优先展示旧宝箱。                         |
| 用户设备时间被修改         | 不改变实际可开启与过期时刻。                               |
| 重复点击购买、开启、退款   | 同一只宝箱最多成功购买、领奖或退款一次。                   |
| 奖励到账后关闭页面         | 历史中奖金额保留；不重复领取。                             |
| 过期时用户不在线           | 系统仍在规定的过期时刻产生并保存一次未领取结果。           |
| 过期后多年未回来           | 仍保留过期奖励结果和应退购买成本；登录时提醒用户申请退款。 |
| 已经过期但用户未点退款     | 钱包余额不增加；该宝箱保持待退款，无法购买新的。           |
| 领取成功后继续游戏         | 新完成的有效游戏才可产生下一轮购买资格；已到账奖金抵减下一次计算的净亏损。 |
| 用户修改语言或换设备       | 显示相同的余额、旧宝箱状态、历史结果与可退款金额。         |
| 运营调整活动规则           | 未购买者按新规则参与；旧宝箱保持购买时确定的合同条件。     |
| 活动停止新的购买           | 已经购买的宝箱仍按既定规则开启或申请退款。                 |

## 08 产品验收标准

下列条目仅验证功能表现与业务结果，不规定技术实现方式。

| 类别   | 验收条件                                                        |
|------------|---------------------------------------------------------------------|
| 资格       | 未完成有效游戏无法购买；完成一局后可购买；资格当日一次性使用。      |
| 购买       | 500 金币只扣一次，成功后有唯一待处理宝箱；余额不足不扣费。          |
| 时间       | 购买次日 00:00 起可开启；次次日 00:00 起不可开启、改为过期待退款。  |
| 分档       | 净亏损不足 5M 为 50%；恰好 5M 为 60%；恰好 10M 为 100%。            |
| 随机上限   | 亏损小于 M 时上限为亏损 L；大于等于 M 时上限为 M。                  |
| 随机下限   | 亏损为 0 时 X 为 0；亏损在 1～9 时 X 固定为 L；其余遵循 [10, U]。 |
| 正常领奖   | 开奖使用开启时对应的统计期数据；奖励到账一次并有明确领奖结果。      |
| 到期预计算 | 过期未领时自动计算并冻结一次“本可获得奖励”，但钱包不会到账。        |
| 主动退款   | 用户未点击退款前余额不变；点击成功后只退实付价一次，退款不计入宝箱收益抵扣。 |
| 奖励抵扣   | 统计期内历史已领取宝箱奖励全额计入 C；例如 G=80,000、W=28,000、C=6,000，L 应为 46,000，适用 50% 档。 |
| 抵扣边界   | 本次待发奖励不抵扣自身；过期未领的预计算奖励不抵扣；购箱扣费及过期购箱退款不影响 L。 |
| 互斥       | 领奖过的宝箱无法退款；退款过的宝箱无法领取此前的奖金。              |
| 循环       | 领奖或退款后需要新的有效游戏，才能重新获得购买资格。                |
| 交互       | 说明和记录可查看；幸运榜默认折叠，展开最多展示当日 5 人。           |
| 多语言     | 默认英文；10 语种可切换，切换不影响宝箱或金币数据。                 |
| 历史       | 用户再次进入页面能看到真实结果，已购老宝箱不被后续配置修改覆盖。    |

## 09 可运营配置与统一口径

| 配置项     | 默认参数                       | 影响范围                         |
|----------------|------------------------------------|--------------------------------------|
| 每次购买价格   | 500 金币                           | 购买扣款、超时退款本金。             |
| 每日购买次数   | 1 次 / 活动自然日                  | 可购买状态和按钮。                   |
| 资格要求       | 完成 1 局有效指定游戏              | 何时出现购买资格。                   |
| 资格有效期     | 完成当日有效                       | 跨日资格是否保留。                   |
| 活动统一时区   | Asia/Shanghai                      | 每日限制、倒计时、榜单、领取窗口。   |
| 开放与过期时刻 | 次日 00:00 开 / 次次日 00:00 过期  | 开启和过期提示。                     |
| 盈亏统计周期   | 最近 7 × 24 小时                   | 亏损 L 的回溯范围。                  |
| 随机上下限     | 10 / 10,000                        | 抽取区间；倍数分档参照上限 10,000。  |
| 折算档位       | `<5M=50%、5M～<10M=60%、≥10M=100%` | 最终奖金计算。                       |
| 奖励取整       | 向下取整至整数金币                 | 最终到账金币。                       |
| 宣传收益文案   | 展示层独立配置                     | 页面标题与营销说明，不改变真实公式。 |

### 9.1 规则使用原则

**奖励逻辑：**用户净亏损同时影响随机数上限与折算比例；奖励仅在实际开启或过期时计算一次，结果固定不可重新抽取。

**过期处理：**未开启宝箱在领取期限结束时产生未领取奖励结果，但不向钱包发放该奖励；购买本金必须由用户主动申请退款后才会返还。

**运营参数：**购买价格、参与门槛、资格有效期、开放与过期时间、亏损周期、随机上下限、比例阶梯、宣传文案和多语言内容可由活动统一配置。已购宝箱沿用其购买时的业务条件。
