# 玩家侧 · 商城

## UI 与功能

商城包含金币礼包、月度特权卡、明日宝箱和购买/流水入口。金币礼包与月卡先打开确认弹窗，展示 SKU、金币/宝石或每日权益、价格、有效天数和不自动续费说明；确认后同一时间只允许一个购买请求。按钮依次反馈处理中、确认中、成功、取消或失败。

完整模式区域顺序为页眉 → 明日宝箱 → 金币礼包 → 已确认的本页购买回执 → 月卡与右侧购买记录；半屏保留宝箱和礼包主卡，月卡/购买记录改为“进入完整大厅”提示。礼包为四列产品卡，每张 `18px` 内边距、`58px` 圆形图标、金额/赠送/价格/CTA 自上而下；推荐卡上移 `4px` 并使用蓝色边线和更深阴影。月卡使用单张带浅蓝径向光的权益卡，主购买按钮和“权益详情”次动作并列。

明日宝箱直接读取 `useEngagement` 的状态：完成当日有效游戏后才可购买，每业务日一箱；购买后等待次日开启，开启后显示奖励或合法的 0 金币结果，并显示截止时间、记录入口和排行榜。购买/开启在处理中锁定，错误显示 alert 和刷新按钮。报价版本不匹配应刷新而不是按旧价成交。

宝箱卡在顶层用暖白/琥珀视觉区别于商品卡：顶部有记录入口，中部依次说明“完成一局 → 购买 → 次日开启”，底部按资格显示锁定说明、购买 CTA、待开启时间、开启 CTA、已开结果或过期状态。加载显示状态文字，错误为 `role=alert` 且附刷新动作；不能只靠按钮禁用表达资格、余额不足或报价过期。

## 支付、资产与服务边界

金币礼包/月卡通过 `JoyloopHost.request('purchase')` 请求宿主支付。只有 `completed` 才展示成功；`cancelled`、失败、超时和宿主不存在均不可展示到账。当前 UI 不从成功回调直接伪造余额、订单或已开通权益，真实余额/权益需宿主或服务端后续上下文刷新。宿主支付桥及真机支付未验证。

明日宝箱使用 engagement adapter：默认是 localStorage preview，可演示资格、余额扣减、开箱和流水；在 server/宿主模式下请求 `/api/v1/chest/*`，购买/开启携带业务幂等键。preview 的跨标签锁不能替代数据库事务，真实原子扣款、开奖、流水、资格、报价 `409` 与排行榜均未验收。

## 验收

- [ ] 金币礼包/月卡确认页完整显示商品与价格，重复点击被锁定，成功只来自 `completed`。
- [ ] 宝箱的加载、资格不足、余额不足、待开启、可开启、已开、过期、stale、失败与刷新均清晰。
- [ ] 购买、开箱和领奖不会在前端提前更新余额或伪造订单。
- [ ] 半屏下商品卡、确认弹窗、宝箱步骤和主要 CTA 仍可触达。
