# 玩家侧 · 大厅

## UI 与功能

大厅是玩家首页。完整模式区域顺序为：最近游戏 → 主区热门游戏与右侧今日赢家榜 → 四张快捷大卡。快捷大卡固定指向转盘、Slots 分类、每日任务、记录。半屏的真实顺序为：热门游戏（第 1）→ 最近游戏（第 2）→ “进入完整大厅”提示（第 3）；`.lobby-quick-actions` 被 `compactLobby.css` 隐藏，**半屏不保留快捷大卡**。半屏仍由 `LobbyPage` 渲染“打开赢家榜”按钮，点击后在框内弹窗展示榜单。

热门游戏采用响应式网格：宽容器默认4列，当前375px手机和430px模拟手机为2列。封面比例 `1.18:1`，角标位于左上 `9px`，正文 `12px` 内边距；卡片标题 `0.82rem`，分类/人数 `0.65rem`。最近游戏在当前手机与模拟手机上为横向可滚动卡片，宽容器可排三列；每张封面 `68px`、整体 `10px` 内边距；窄屏改为横向 snap 列表。快捷大卡仅完整模式显示，宽容器4列、手机与模拟手机2列；卡内 `14px`、`42px` 图标块、名称与说明两层文字。

最近游戏根据玩家的“好友可见最近游戏”偏好显示“仅自己/好友可见”提示。横向列表可用左右方向键滚动，并遵从减少动态效果设置。热门游戏复用游戏目录规则，点击只打开详情，不直接启动。

赢家动态与榜单是动态数据：加载中显示状态，空数据给空态，失败不得伪造中奖事件。点击赢家事件只有在该游戏对当前国家开放时才可进入该游戏详情；不开放时显示提示而不是绕过地区限制。

## 状态反馈与边界

- 游戏存在维护、即将上线、不可用或门槛时，封面覆盖 `rgba(12,24,45,.72)` 深色层和白色粗体状态；门槛卡另在正文显示琥珀色 `0.68rem` 原因，仍可打开详情解释。
- 当前赢家、最近游戏和游戏目录中的静态样例不能证明在线人数、中奖金额或实时流已连接。
- 赢家流由 `engagement.winners` 提供；默认 preview adapter 会生成演示事件，服务端模式的响应格式、轮询和错误恢复待 API 验收。

## 验收

- [ ] 完整与半屏的信息优先级符合上述结构：半屏隐藏快捷大卡，赢家榜通过“打开赢家榜”弹窗入口保留。
- [ ] 最近游戏、热门游戏、赢家点击全部遵守地区过滤；键盘横滚可操作。
- [ ] 赢家加载/空/失败/暂停状态可辨，失败不会显示旧样例为实时结果。
- [ ] 快捷入口携带当前语言与模式参数，返回后滚动位置合理恢复。
