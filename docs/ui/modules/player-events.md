# 玩家侧 · 活动

## UI 与功能

活动页包含七日签到、幸运转盘、每日任务与奖励记录入口。活动配置读取已发布的静态配置：转盘当前 8 格、每日免费次数与奖项概率；地区按签到/转盘/任务分别判断。某项活动不在玩家国家范围内时整段不渲染；全都不开放时显示活动不可用状态。

完整模式区域顺序为页眉 → 无可领取时的绿色状态条 → 今日概览卡 → 签到 → 转盘 → 任务。概览卡左侧是可领取数量，右侧三张跳转卡；签到为 7 列网格，转盘与任务各为独立卡片。半屏改为紧凑头部、签到行、转盘行、前两条任务和“更多任务”提示，不显示完整的七日网格或转盘图面。

签到展示连续七日、今日、已领取、漏签和大奖视觉。当前页面点击只演示领取今日奖励。转盘在旋转中锁定，遵从减少动态效果；免费次数为零时禁用。任务展示目标、进度、奖励、过期/可领取/已领取状态；已达成且未过期才可领取。奖励记录当前仅记录本页会话内的演示操作。

签到日卡最小高 `132px`、`13px` 内边距、`14px` 圆角；今日为蓝色边线/浅蓝底，已领取为绿色底，漏签虚线并降至 `.72` 透明度，大奖为琥珀色底。可领取任务卡使用浅蓝边线和阴影，奖励用浅蓝小标签；转盘按钮旋转中禁用，记录按钮同时禁用并显示等待态。所有状态必须有文字，颜色仅作辅助。

## 当前服务边界

此页的签到领取、转盘抽奖、任务领取、次数、奖励记录均是 `EventsPage` 本地状态演示，当前不会请求奖励服务、改变钱包或产生可追溯领取记录。页面使用静态已发布配置仅保证前后台原型看到同一组配置数值，不能证明真实资格、概率抽样、库存、结算或幂等。

真实实现须由服务端返回活动配置版本、地区资格、进度、剩余次数、领取状态和业务唯一领取键；前端在响应前锁按钮，只在确认结果后更新状态。网络失败须保留原进度并给重试，不能先把按钮改成“已领取”。
